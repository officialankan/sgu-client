Client#

SGUClient is the entry point for every request. Endpoints are grouped by domain on its attributes:

Attribute

Client

client.levels.observed

ObservedGroundwaterLevelClient (Observed groundwater levels)

client.levels.modeled

ModeledGroundwaterLevelClient (Modeled groundwater levels)

client.chemistry

GroundwaterChemistryClient (Groundwater chemistry)

See Getting started for an introduction.

SGUClient#

class SGUClient(config=None, *, transport=None)[source]#

Main client for interacting with SGU API.

This is the primary interface users will interact with.

Use it as a context manager so the HTTP session is closed when you are done. If the client has to outlive a with block, call close() yourself.

Example

>>> with SGUClient() as client:
...     stations = client.levels.observed.get_stations()
...     measurements = client.levels.observed.get_measurements()

>>> # With custom config
>>> config = SGUConfig(timeout=60, log_level="DEBUG")
>>> with SGUClient(config=config) as client:
...     stations = client.levels.observed.get_stations()
__init__(config=None, *, transport=None)[source]#

Initialize the SGU client.

Parameters:

  • config (SGUConfig | None) – Configuration object. If None, uses default config.

  • transport (Transport | None) – Where requests go. If None, the client talks to SGU over the network with a RequestsTransport built from config, and closes it in close(). A transport you pass in is yours to close, and the network settings in config (timeout, max_retries, user_agent) don’t apply to it.

LevelsClient#

class LevelsClient(base_client)[source]#

Client for accessing groundwater level data.

Provides access to both observed and modeled groundwater levels through a hierarchical API structure.

Example

>>> with SGUClient() as client:
...     stations = client.levels.observed.get_stations()
...     areas = client.levels.modeled.get_areas()
...     levels = client.levels.modeled.get_levels()

Transports#

Every request goes through a Transport. By default that’s a RequestsTransport, which talks to SGU over the network using the timeout, max_retries and user_agent from SGUConfig.

Pass your own transport to serve responses from somewhere else, for example canned pages in your tests. A transport has one method, fetch, which returns the status and body of one response; the client still handles errors, JSON and pagination:

import json

from sgu_client import SGUClient, TransportResponse

class CannedTransport:
    def __init__(self, page: dict):
        self.page = page

    def fetch(self, url, params):
        return TransportResponse(200, json.dumps(self.page))

client = SGUClient(transport=CannedTransport(my_station_page))
stations = client.levels.observed.get_stations()

A transport you pass in is yours to close; SGUClient.close() only closes the transport the client created.

class Transport(*args, **kwargs)[source]#

Fetches one response from SGU.

The client builds the URL and query params, then decides what the response means: it turns error statuses into SGUAPIError, parses the JSON and requests further pages.

A transport raises SGUTimeoutError or SGUConnectionError when it can’t get a response at all.

class RequestsTransport(config=None)[source]#

The default transport: GET requests to SGU with the requests library.

Uses timeout, max_retries and user_agent from the config. Retries on 429 and 5xx responses with exponential backoff.

Parameters:

config (SGUConfig | None) – Configuration object. If None, uses default config.

fetch(url, params)[source]#

GET url with query params and return the response.

Raises:

  • SGUTimeoutError – If connecting or reading times out.

  • SGUConnectionError – If SGU can’t be reached.

  • SGUAPIError – If the request fails in any other way.

Return type:
